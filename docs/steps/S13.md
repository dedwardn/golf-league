# S13 Services for play

**Implemented**

`league.services` now holds code: `services/play.py` with the three play use cases. A link token finds its player. A card is stored only when `accepts_card` takes it (R13), as the player's own card or, in a shared-ball round, as their team's team card (R15), and every refusal raises `ValueError`. A player's season view is `compute_season` with the rounds R12 hides from them taken out, and its standings and segments are the same for every viewer. The admin's view keeps every round. To make this possible, players now carry a link token in the store, and `access.py` exposes whether a round takes team cards.

**Deviations from plan**

- `submit_card` takes a `Submission` instead of six arguments. The architect ruled this and the owner chose it (answer 2(a)) before the build.
- The refusal message is `round N does not take this card`. The tests match on it because ruff's PT011 rejects a bare `pytest.raises(ValueError)`. The match also shows that the refusal came from the service and not from the database.
- In `load.py` the local `players` is renamed `seeded`. The plan didn't mention it. Importing the `players` table would otherwise have been shadowed.
- One test name is shorter: `test_r13_late_card_at_late_until_is_stored`. The test checks exactly `now == late_until`.
- The late-card and after-close tests use T3 round 1 and hal, per architect ruling 13(c). T3 is a team season and round 1 is own-ball, so R13's acceptance rule is tested there rather than in an individual season. That rule doesn't depend on the season's mode.
- `pyproject.toml` changed, at the owner's request.

**Open questions**

- **Settled by the owner (audit finding 4):** a late card in a team season is accepted and stored, because R13's acceptance rule doesn't depend on the season's mode. It would then score nothing, because R15 says a team season scores none. The owner chose the architect's option (b), but carried out through S14 rather than R15. A team season has no late window, because a missed round is the round that is dropped. BUILD_PLAN S14's accept line now says the use cases offer no `late_until` in a team season, and SPEC section 6, decision 4, records it as settled. No domain change. S13's tests that put `late_until` on T3 round 1 stay, since `access.py` still answers R13 the same in any season.
- **Answered, no longer open (audit finding 3):** `submit_card`'s `facts.teams[player_id]` can only fail when an individual season has a round with a shared-ball format. SPEC section 2 lists that under Never, and D16 rules out team cards in an individual season. S14's accept line already creates a format only in a team season. A bare `KeyError` is the loud failure for an input nothing creates, so neither `submit_card` nor `SeasonFacts` guards it.

**Audit**

The reviewer made 9 findings; the architect ruled on each.

1. `with_round` duplicated `tests/domain/conftest.py`'s helper. Applied differently: `test_play.py` no longer defines it, and `s9b_open`, `t3_open` and `t3_late` build their rounds directly. Moving the helper to `tests/fixtures/` would have touched domain test files outside the step.
2. The shared-ball split lives in `access.py` and `season.py`. Declined. S13 made an existing private check public, as BUILD_PLAN S13 says. Merging the two would touch `season.py` and need a new union alias that no behaviour needs. A sixth format gets its own step.
3. A shared-ball format in an individual season makes `submit_card` raise `KeyError`. Declined: the documents already rule that input out (see Open questions).
4. A late card in a team season is stored but never scores. No code change. The owner settled it: S14 offers no `late_until` in a team season (see Open questions).
5. The last assertion in `test_r12_admin_sees_every_round` looked redundant. Declined. It is the only line that fails if `compute_season` ever drops an open round.
6. The draft round expression is repeated, and `a_card` and `PLAYED` are still imported from `test_save.py`. Declined. Moving them shifts lines without removing any, and S12 put `a_card` and `PLAYED` there.
7. A sentence in `play.py`'s docstring repeated ARCHITECTURE. Applied: the docstring keeps only the sentence about `now`.
8. ARCHITECTURE's "one revision per schema change" contradicted editing the s11 migration. Applied as a doc edit to the store map's migrations row: until S18 a schema change edits S11's one revision, and from S18 each change is a revision of its own.
9. The link-token tests cite no rule. Declined. No numbered rule covers link tokens, and `test_migrations_build_the_tables_the_store_reads` is the precedent for a test name with no rule.
