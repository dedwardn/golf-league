# S3 Sides and compare

**Implemented**

Net cards now become the two things a contest needs. `single_side` wraps one player's
net card, `bestball_side` takes the lowest net score per hole across a side's members
and reports a side with no card as missing, and `virtual_side` averages the best
`virtual_n` reference cards per hole, falling back to net par when none is left (R7).
`compare` puts two sides against each other on holes, total or stableford (R8).

**Public API**

```python
# results.py
@dataclass(frozen=True)
class NetEntry:
    card_id: str
    player_id: str
    submitted_at: datetime
    net: NetCard

@dataclass(frozen=True)
class Side:
    player_ids: tuple[str, ...]
    net: NetCard

@dataclass(frozen=True)
class Comparison:
    winner: Side | None
    margin: int

# sides.py
def single_side(entry: NetEntry) -> Side
def bestball_side(members: Sequence[NetEntry]) -> Side | None
def virtual_side(
    references: Sequence[NetEntry],
    opponent_player_ids: Sequence[str],
    tee: Tee,
    virtual_n: int,
) -> Side

# compare.py
Basis = Literal["holes", "total", "stableford"]
def compare(a: Side, b: Side, basis: Basis, tee: Tee) -> Comparison
```

`NetEntry` carries what a rule produced and the identity of what produced it, and
nothing it consumed: the tee and the index the card was played off are arguments to
`net_card` and stop there. Every field is read by this step, `card_id` and
`submitted_at` by the tie for the last virtual place.

`compare` takes `tee` although only the stableford branch reads it. The alternative is
a caller that switches on basis before calling, which moves R8's own decision outside
R8's module.

The three bases normalise to "higher wins", with the net total negated so one
comparison serves all three. `holes` counts only holes actually won, so a halved hole
needs no special case.

**Deviations from plan**

1. The plan's "an empty reference set is net par" became one test covering both ways a
   virtual side runs out of cards: an empty reference list, and every reference
   excluded as an opponent. R7 gives one outcome for "if no card is left", and the
   second path reaches it through different code.
2. Two tests assert fields rather than whole objects: `side.player_ids` in the bestball
   test, `result.winner` and `result.margin` in the R8 example. Vulture reported those
   three fields as unused, which was true. Whole-object equality passes without ever
   reading a field, so the tests were fixed rather than the gate, and the virtual test
   now states that a virtual side has no players.
3. The comment on the `else` branch of `compare` names `total`, at the owner's request
   after the code was read. It explained the sign flip without saying which basis it
   belonged to.

Applied at audit:

4. `test_r7_bestball_leaves_out_a_member_without_an_on_time_card` is deleted, not
   renamed. The function never sees the absent member, so the test could not fail for
   the reason its name cited: the leaving-out is the caller's filtering. The criterion
   moves to S4, with the code that does the filtering. The owner records that the S3
   accept line named behaviour the step cannot exercise.
5. The rationale for a virtual side having no players is stated once, on `Side` in
   `results.py` where the empty tuple lives, and removed from `virtual_side`'s docstring
   and from a test comment.
6. `NetEntry`'s second docstring paragraph is gone. It restated ARCHITECTURE's results
   convention rather than this class, and a convention copied into every result class
   lives in eight places instead of one.

Rejected at audit, both because R7's knowledge stays in R7's module:

7. `bestball_side` keeps `Side | None`. Returning a `Side` for no members yields a side
   with zero holes, which survives until `compare`'s strict zip; and R7's missing side
   has to be said somewhere, which this module can do because an empty sequence of
   entries is in its own vocabulary. The docstring now carries that clause so it is not
   relitigated at S4.
8. `single_side` stays. Deleting it moves "a single side's players are exactly the
   card's owner" into the contest module, which is a piece of R7.

Nothing else differs. The five planned files are the five files changed, the public API
is as approved, and `reference_tees` is absent as ruled.

**Deliberately not done**

  module never sees; S4 owns it and its accept line.
- Building `NetEntry` from real cards, which is where R7's allowance sentence is
  applied. S4 and S9.
- Contests, pairings, awards, multipliers, late cards, `closed_at`, `ContestConfig`.
- Validating `virtual_n`. The home is `ContestConfig` in `facts.py`, as R5's bounds sit
  on `IndexRule`. Recorded for S4 by the owner.

**Open questions**

1. `virtual_side` is silent on a `virtual_n` it cannot honour: 0 gives net par and a
   negative value keeps everything except the worst card, both wrong answers rather
   than errors. Harmless until a config can carry the number, so the check belongs to
   `ContestConfig` at S4. Noted by the owner at review, repeated here so it is not lost
   if that step is planned from this report.
2. Settled at audit, kept here because it was raised here. Missing sides reach S4 in
   two shapes: `bestball_side` returns `None`, while a missing single side is the
   caller having no entry to pass. That is not an inconsistency but the absence made
   unrepresentable in each input's own form, so S4 handles both and `single_side` does
   not become optional. The reason now lives on `bestball_side`'s docstring.
3. The glossary defines a side as "one net card, a best ball of several, or a virtual
   side". `Side` also carries the players who earn its points, which is what R9 needs
   and what the glossary's pairing line implies. The glossary line may want that added;
   I have not edited it.
