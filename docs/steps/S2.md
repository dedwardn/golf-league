# S2 Index

**Implemented**

A card now turns into a differential and a differential moves an index.
`differential_tenths` caps each gross hole at par + 2 + strokes and rebases the total
onto slope 113 (R4), `next_index_tenths` moves the old index toward it at the rule's
rate, clamped to -5.0 and 54.0 (R5), and `index_by_card_tenths` replays one player's
counted cards from their seed to give the index each card was played off (R6).

**Public API**

```python
# rounding.py
def round_half_up(value: Fraction) -> int

# facts.py
@dataclass(frozen=True)
class Card:                      # changed: two fields added ahead of scores
    card_id: str
    submitted_at: datetime
    scores: tuple[int, ...]

@dataclass(frozen=True)
class IndexRule:
    early_rate: int
    early_cards: int
    rate_down: int
    rate_up: int

# index.py
def differential_tenths(card: Card, tee: Tee, index_tenths: int) -> int
def next_index_tenths(
    old_tenths: int, differential_tenths: int, rule: IndexRule, use_early_rate: bool
) -> int
def index_by_card_tenths(
    seed_index_tenths: int,
    provisional: bool,
    cards_with_tees: Sequence[tuple[Card, Tee]],
    rule: IndexRule,
) -> dict[str, int]
```

`round_half_up` serves both uses and there is no second rounding helper. R1 rounds to a
whole stroke; R4 and R5 round to one decimal. These are the same operation, because
one-decimal values are held in tenths, so rounding to one decimal is rounding the tenths
value to an integer. It sits in its own module rather than in `strokes.py` because it
implements the Arithmetic paragraph, not R1 to R3: left there, R7 would have had
`sides.py` importing `strokes.py` purely to get arithmetic, an edge that describes
nothing true.

**Deviations from plan**

1. `round_half_up` moved to a new `domain/rounding.py`. The approved plan proposed
   promoting it inside `strokes.py`; the owner ruled otherwise at approval and added the
   module-map row and a convention covering when a constant follows.
2. `Card` gained two fields, not the three the plan proposed. `round_number` was removed
   at audit: R6 now breaks a tie on card id, so the field had no reader, and keeping it
   would have let `RoundFacts` and `Card` both claim the round's number once the store
   exists.
3. The duplicate `card_id` check in `index_by_card_tenths` was added by the owner at
   approval and kept at audit. R13 now states that a card's id is unique within a season,
   so the check implements a rule rather than inventing one. Its test is named
   `test_r13_a_repeated_card_id_is_an_error` for that reason.
4. `IndexRule` validates its bounds. The plan left this conditional on Question 3. The
   owner answered by first writing the bounds into R5, so the check describes the spec
   rather than inventing behaviour.
5. The conftest helper is `a_card`, not `card` as the plan and the owner both wrote. It
   matches `a_tee` and does not shadow the `card` loop variable in the replay tests.
   Confirmed by the owner after the fact.
6. The single planned ordering test became two: one for `submitted_at`, one for the
   card-id tiebreak. One test asserting both would not say which rule failed.
7. Two test names changed. The blow-up test lost `_plus_strokes` because the hole it uses
   receives no stroke, and a separate test covers a stroke raising the cap. The
   provisional test is now `test_r5_the_early_rate_is_used_whichever_way_the_index_moves`,
   which is what it asserts.
8. Two tests annotate `gross: list[int]`. Pyright strict infers `list(PARS)` as
   `list[Literal[4, 3, 5]]` and rejects assigning 7 or 9 into it.
9. The audit asked for `MAX_RATE` and `FULL_ALLOWANCE` to be inlined. `FULL_ALLOWANCE`
   was. `MAX_RATE` could not be: `PLR2004` rejects a bare `100` in a comparison, and the
   gate is not weakened to pass it. The defect the audit named was the asymmetry, so
   `MIN_RATE` was added alongside it and the message now interpolates both ends.

The replay tests use rules with rates of 0 and 100, both legal under R5, so every expected
index is hand-computed: 0, 18.8 and 49.9. This is deliberate and should not be tidied away.
A replay test whose expected value comes from calling `differential_tenths` and
`next_index_tenths` asserts only that the code equals itself and cannot fail.

`test_r4_capped_total_95...` asserts `sum(card.scores) == 95` before calling the function.
That line pins the fixture, not the code. Without it, an edit to `SCORES_95` would leave
the test passing while it proved something other than the R4 worked example. It is not
dead weight and should not be removed as a test of a literal.

**Deliberately not done**

- Choosing seed indexes, and storing the `provisional` flag. It is a parameter here; the
  fact belongs to S11 and S14.
- Values for `IndexRule`'s four numbers. Open decision 1 is unresolved, so the dataclass
  has no defaults and every caller supplies all four.
- Splitting a season's cards by player and feeding this function. S9 owns that.
- `TENTHS` and `SLOPE_BASE` stay in `strokes.py`. `index.py` already depends on it because
  R4 uses R2's strokes at allowance 100, so the import rides an edge that already exists.
- A test for a player with no cards. See below.

**Open questions**

1. `index_by_card_tenths` returns `{}` for a player with no cards. Verified, and correct
   for a dict keyed by card id, but it means the function reports no index at all for
   someone who has not played, although their seed index is their index. S9 builds a view
   for every player in a season including those, so it needs the seed from elsewhere.
   Decide at S9 whether that is the caller's job or whether the return type is wrong.
2. Open decision 1 is still open. The three rates and `early_cards` have no agreed values,
   so nothing in the tests should be read as endorsing 70 / 3 / 50 / 30.
3. The glossary defines a card as "18 gross hole scores for one round, with
   `submitted_at`". It now also carries `card_id`, which R13 requires. The glossary line
   may want that word added; I have not edited it.
