# S5 Field and allplay contests

**Implemented**

A field contest and an allplay contest now turn their config and the round's net entries
into awards, from on-time single sides only. A field player's position is one more than
the sides that beat them under R8, tied players share the mean of the positions their
group covers, and a position past the end of `position_points` scores 0. An allplay
player earns `scale * (wins + draws / 2) / (n - 1)`, and with one card there is no award.

**Where**

| File | Holds |

| `src/league/domain/facts.py` | `DuelConfig`, which is S4's `ContestConfig` renamed, plus `FieldConfig` and `AllplayConfig`. One frozen record per kind, so no contest carries a field that means nothing to it. `FieldConfig` rejects basis `holes`. |
| `src/league/domain/results.py` | `DuelReason` is the three duel outcomes, `Reason` is that alias widened with `position` and `record`, the reason names the glossary states. `Award.reason` takes `Reason`. |

| `tests/domain/test_facts.py` | One shape test: a field config cannot rank on holes. |

84 tests, 100 percent coverage of `league.domain`. 211 added lines, 21 removed. Each
accept criterion has one test: tied positions share, positions beyond the list,
the allplay example, allplay with one card, late cards ignored in both, basis holes
rejected, and a record of exactly one third. Also edited at `/finish`:
`docs/ARCHITECTURE.md` (module map) and `docs/BUILD_PLAN.md` (status).

**Public API**

```python
# facts.py
@dataclass(frozen=True)
class DuelConfig:  # S4's ContestConfig, renamed. Fields unchanged.
    ...

@dataclass(frozen=True)
class FieldConfig:
    key: str
    basis: Basis
    position_points: tuple[Fraction, ...]
    multiplier: int = 1

@dataclass(frozen=True)
class AllplayConfig:
    key: str
    basis: Basis
    scale: Fraction
    multiplier: int = 1

# results.py
DuelReason = Literal["win", "draw", "loss"]
Reason = DuelReason | Literal["position", "record"]

# contests.py
def field_awards(
    entries: Sequence[NetEntry],
    tee: Tee,
    closed_at: datetime | None,
    config: FieldConfig,
) -> tuple[Award, ...]

def allplay_awards(
    entries: Sequence[NetEntry],
    tee: Tee,
    closed_at: datetime | None,
    config: AllplayConfig,
) -> tuple[Award, ...]
```

Both return awards in entry order, one per on-time player, with the multiplier applied.
Both take `tee` because a stableford basis needs the pars, and `closed_at` because R9
keeps late cards out of the ranking and out of `n`.

`FieldConfig.basis` is the wide `Basis` with a run-time check rather than a narrower
`Literal`. The narrow type would make the check unreachable and the test unwritable,
and config arrives from JSON at S11, which no type reaches. This polices which values
are allowed, not which fields exist, so it is not the pattern option A was chosen over.

**Deviations from plan**

1. `Reason` is two aliases, not one. The plan had a single widened `Literal`, which left
   the duel's private award helper advertising both ranking reasons in its signature
   and raising `KeyError` on either. `_side_awards` now takes `DuelReason`, so pyright
   rejects those two at the call site. The owner ruled on this during the step.
2. The basis test is named `test_r9_a_field_ranks_on_total_or_stableford_never_holes`
   rather than the planned `test_r9_field_rejects_basis_holes`, citing the message the
   check raises, as S4's shape tests do.
3. One test was added after the plan, on the owner's amended accept line:
   `test_r9_allplay_records_of_one_third_are_exact`. It asserts each record equals
   `Fraction(1, 3)` exactly. The criterion first read that three float thirds would not
   sum back to whole; they do, and the criterion and D14 were corrected. The test catches
   a float implementation through the exact equality, not through the sum.

Nothing else differs. The five planned files are the five files changed, and the ranking
is the planned one: one plus the number of sides that beat you under `compare`, so the
direction of better stays in R8 and ties need no second code path.

Applied at audit:

4. The second assertion of the one-third test is deleted. With each record pinned to
   `Fraction(1, 3)`, the sum of the three is arithmetic and could not fail.
5. `an_allplay` loses its `basis` parameter. Its one caller passed `"holes"` over a
   fixture of identical net par cards, where every basis gives the same wins and draws,
   so the parameter exercised nothing. S3 tests all three bases on `compare`.
6. The allplay reason is `"record"`, not `"share"`. SPEC's arithmetic paragraph already
   uses "share" for a percentage, and one name means one concept. The glossary's `award`
   entry now names all four reasons, so `results.py` implements a stated vocabulary
   instead of inventing one, as the `virtual_n` bound did two steps ago.

**Deliberately not done**

- Teambonus and manual awards. S6, which also splits `test_contests.py` by kind first.
- `kind` on the three configs and the `ContestConfig` union alias over the four. S9,
  which dispatches on it.
- `allowance` and `reference_rounds` on `DuelConfig`, and resolving reference rounds. S9.
- Late cards in field contests. Open decision 4 asks whether they should later be placed
  against the frozen on-time field. Nothing here builds toward it.
- Bounds on `position_points` and `scale`. R9 states none.
- Countback for tied positions. R9 says tied players share.

**Open questions**

1. `Award` cannot say which position earned a field award, so the round page can show
   only "position", not "2nd in the field". The field belongs to the step that reads it,
   which is S13 or S16.
2. `field_awards` and `allplay_awards` compare every pair of sides, which is about 400
   comparisons for a 20 card field and cheap. If a later format ranks a much larger
   field on `total`, sorting on the net total would be the faster route, at the cost of
   teaching this module which direction each basis runs.
