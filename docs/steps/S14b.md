# S14b Services for admin: run a round

**Implemented**

- `change_round` replaces a draft round's tee, window, contests, format and `late_until` under `create_round`'s checks, and refuses any round that is not a draft (R14).
- `open_round` opens a draft round once every duel contest of it has published, non-empty pairings (R14, R9). `close_round` closes an open round and records `now` as `closed_at` (R13).
- `reopen_round` undoes a close for a closed round with no late card or late team card, which clears `closed_at` (R13, SPEC decision 7 as settled by the owner in this step).
- The database refuses a closed round without `closed_at` and any other round with one.
- A team season's seed indexes are locked while any round is closed, no longer only once round one has closed (owner's answer to audit finding 2).

**Audit**

The reviewer made 5 findings; the architect ruled on each.

1. A reopened round takes cards from players who saw its results while it was closed (R12, R13). Sent to the owner, who chose to keep the behaviour and state it. As SPEC stood the code was right: R13 accepts a card while a round is open, and R14 says a reopened round is open. A gate in `accepts_card` would need a new fact, since a reopened round's facts equal those of a round never closed. SPEC R13 gains the sentence, and one test pins it.
2. Reopening round one unlocks seed index correction in a team season (R15, D17). Sent to the owner, since D17 is a decision. The real gap: with round one reopened and a later round still closed, `seed_index_locked` was False and a correction would rewrite closed rounds. The owner chose a lock that holds while any round is closed, applied in `access.py`, its tests, SPEC R15, D17 and BUILD_PLAN S14a.
3. Three ways to find a round by number. Applied: `load_round(connection, season_id, number, state)` replaces `load_draft_round`, `_season_round` and `close_round`'s own state test are gone, and `close_round` no longer loads the whole season. `test_r13_load_round_reads_only_a_round_in_that_state` adds an open-round case, so a `load_round` that ignored `state` would fail.
4. A stored `state` is derived from `closed_at`. Declined: SPEC section 4 lists state and `closed_at` as separate facts, the state carries draft versus open, which `closed_at` cannot, and ARCHITECTURE and S14b's accept line ask for the CHECK.
5. This report listed only the service tests of `may_reopen`. Applied: the domain tests are named too.

Doc edits from the architect, applied in this step: the `store/load.py` row of `docs/ARCHITECTURE.md` and S14b's module line in `docs/BUILD_PLAN.md` name a round of one number in one state.
