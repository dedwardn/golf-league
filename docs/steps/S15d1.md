# S15d1 A tee's course and name

**Implemented**

- A tee is identified by its course and tee name, as Trackman lists them. The separate tee id is gone from `src` and `tests`, docstrings included.
- The store keys `tees` on the two together, and a round's tee is a composite foreign key onto them.
- A caller that holds a tee passes the `Tee`. A caller that only names a tee passes its course and tee name.
- Home heads a round with its course and then reads "White tee · Closes ...", as drawn.

**Audit**

The reviewer made 6 findings and read the code without running it. The architect ruled on each.

1. `load_tee_named` duplicated `stored` in `tests/services/test_setup.py`. Accepted: one `stored(engine, course, tee_name)`, called with `*on(...)`, and `load_tee_named` deleted.
2. `save_whole_round` kept a stored tee of the same course and name even if its numbers differed, and read the whole table. Accepted: it looks up only that course and name, saves the tee when no row holds it, and otherwise asserts the stored tee is this one.
3. A tee's key columns are spelled out twice in `save.py`, and the two-column match four times. Declined: a helper would cost a function and a spread to save two lines, and the conditions stay apart across `load.py` and `save.py`.
4. `change_tee` on a tee nobody stored changes nothing silently, and `create_round` on one raises `NoResultFound`. No code change, since it predates the step and SPEC states no refusal. Sent to the owner, above.
5. SPEC sets no bound on a tee's names. No code change, since code enforces only the bounds SPEC states. Sent to the owner, above.
6. The Tee B sentence in T3's fixture docstring split Tee A's reasoning. Accepted: moved after it.
