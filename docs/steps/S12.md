# S12 Store, write side

**Implemented**

Each fact the tables hold now has its own save function in `store/save.py`. Each one writes on
the connection its service hands it and never commits. A JSON column is written through the same
pydantic adapter that `load.py` reads it back with. Those adapters moved from `load.py` to
`schema.py` so the two directions share them. A season team is written onto its players'
seeded rows. S11's hand-written test row writers are gone: every round trip now saves through
these functions and loads through `load_season_facts`.

**Public API**

```python
# schema.py
CONTESTS_JSON: TypeAdapter[tuple[ContestConfig, ...]]
FORMAT_JSON: TypeAdapter[FormatConfig]
INDEX_RULE_JSON: TypeAdapter[IndexRule]
STANDINGS_RULE_JSON: TypeAdapter[StandingsRule]
PAIRINGS_JSON: TypeAdapter[Mapping[str, tuple[Pairing, ...]]]
HOLES_JSON: TypeAdapter[tuple[int, ...]]

# save.py
def save_player(connection: Connection, player_id: str) -> None
def save_tee(connection: Connection, tee_id: str, tee: Tee) -> None
def save_season(connection: Connection, season_id: str, mode: str, index_rule: IndexRule, standings_rule: StandingsRule) -> None
def save_seeded_player(connection: Connection, season_id: str, player_id: str, seed_index_tenths: int, provisional: bool) -> None
def save_season_team(connection: Connection, season_id: str, team_id: str, player_ids: tuple[str, ...]) -> None
def save_round(connection: Connection, season_id: str, round_: RoundFacts, tee_id: str, state: str) -> None
def save_card(connection: Connection, season_id: str, round_number: int, player_id: str, card: Card) -> None
def save_team_card(connection: Connection, season_id: str, round_number: int, team_id: str, card: Card) -> None
def save_manual_award(connection: Connection, season_id: str, round_number: int, award: ManualAward) -> None
```

`save_round` takes the shape the owner chose (option A). It writes the round's number, contests,
pairings, format, `closed_at` and `late_until` on the tee `tee_id` names. It does not read
`round_.tee`, `round_.cards`, `round_.team_cards` or `round_.manual`, and its docstring says so.

**Deviations from plan**

- `save_whole_round` takes an optional `state`. The draft-round test needs it to save a round as
  draft. Otherwise the helper derives `open` or `closed` from `closed_at`.
- `load(engine, season_id)` moved to `test_save.py` with the round trips, and `test_load.py`
  imports it. `test_schema.py` imports `PLAYED` as well as the helpers.
- `test_save.py` gains `void`, a raw update scoped to its season, which `test_load.py` and
  `test_schema.py` both use (audit finding 4).
- About 380 lines added and 263 removed in `src` and `tests`. Most of the removal is S11's row writers, and most of
  the addition is `save.py` and the helpers and tests that moved into `test_save.py`.

**Deliberately not done**

- Voiding and correcting a card, opening and closing a round, correcting a seed index, and
  changing a tee: S14, in `store/save.py`. Until then, tests void a card with a raw `update`.
- Link tokens, sim names, names, and a round's `opens_at` and `closes_at`: S13 and S14.
- A save for a whole season in `src`. Services save one fact at a time.
- Any check in save. A save that takes a domain dataclass gets one its own `__post_init__` has
  checked, and keys and CHECKs refuse what breaks them. `save_season`'s `mode`,
  `save_seeded_player`'s seed index and provisional flag, and `save_season_team`'s players are raw
  values that no dataclass has seen. A bound that spans facts, such as R9's manual award naming a
  competitor or R15's team of two in a team season, is checked only on load. A bad value is then
  refused only after it is stored, and from then on the season does not load. S14's services
  validate a new fact with a domain function before they save it, as ARCHITECTURE's data flow says.

**Open questions**

- Through `load_season_facts`, open and closed look the same: it reads `state` only to leave out
  draft rounds. A `save_round` that wrote `open` for a closed round would pass every round trip.
  Only the draft test pins `state`. This joins S11's question, carried to S14, of whether the
  database should tie `state = 'closed'` to `closed_at` being set. `save_round` also takes
  `state`, `closed_at` and `late_until` as separate values, so a caller can save them disagreeing.
  The round trips need all three today, because load leaves out draft rounds. Once S14 opens and
  closes a round as an update, S14 decides whether `save_round` keeps them.
- `save_season_team` checks neither how many rows it changed nor whether a player is already in
  a team. A team naming a player who is not seeded writes nothing for that player. In a team
  season this fails on load, through R15's team-of-two check. In an individual season it goes
  unnoticed. A team naming a player already in another team moves that player without an error,
  which changes a stored fact and so is S14's. S14's season-teams use case decides whether the
  service refuses both cases first, and whether a player's team may change at all.

**Audit**

The reviewer made 7 findings; the architect ruled on each.

1. `save_season_team` can move a player already in a team. Declined in code: a `team_id IS NULL`
   condition turns the move into a silent skip and refuses nothing. Changing a player's team is a
   change of a stored fact, which is S14's. Added to the open question.
2. `state` and `closed_at` are written separately by `save_round`. No code change. Carried to S14
   in the open question.
3. The report said every saved value arrives checked. Applied: three saves take raw values, and
   bounds across facts are checked only on load.
4. The `database` fixture is in three test files. Declined, as at S11 audit finding 6 and plan
   ruling 9. The repeated raw void: applied, as `void` in `test_save.py`.
5. Two golden round-trip names cited no rule. Applied: `test_r13_the_golden_season_round_trips`
   and `test_r15_the_golden_team_season_round_trips`.
6. Nothing observes `open` against `closed`. Already stated, and carried with finding 2.
7. `save_round` does not read `round_.tee`. Noted only, as the owner's option A.

After the audit `./scripts/check.sh` passes: 265 tests, 100 percent coverage.
