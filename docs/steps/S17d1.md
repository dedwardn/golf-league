# S17d1 Courses: the stored tees

**Implemented**

- The Courses tab, `/admin/tees`, lists every stored tee, ordered by course and then tee name ignoring case, with each name shown as typed. Each row reads its course, with the tee name at the row's right, and opens that tee's "Change a tee" page.
- Add a course and tee, a full-width primary button at the top, opens the empty form, which now lives at `/admin/tees/new`. Save tee still posts to `/admin/tees`.
- With no tee stored, Courses shows Add a course and tee and no card. Every Courses route refuses a visit without the admin cookie, and each reads the admin nav with Courses marked.
- The layout follows `admin-player.html`'s blocks and roster rows (the owner's answer (a)). A long course name may wrap, and the tee name keeps its place at the right.

**The audit**

The reviewer raised five findings, and the architect ruled on them:
- **1, split in two.**
  - **The status: declined.** A step marked done before the click-through stands while nothing is committed (as in S15a and S15b). S17d1 is committed only after the owner's phone click-through.
  - **The criterion: sent to the owner.** The Accept's wrap clause cannot be met with the course it names, by the arithmetic above. This report's guess is replaced with that arithmetic.
- **2, applied in the new file.** `admin-courses.html`'s note reads "Rounds joins with S17d2." The same stale notes in the other three templates are outside this step's files, and S17d2's plan deletes them.
- **3, declined.** The tee page's URL is built once in `admin.py`'s redirect and once in the template's row links. Add a player already splits its URL the same way (`admin.py` and `admin-player.html`). Giving the URL one home would move code without reducing it, and the tests cover both encodings.
- **4, declined.** The card's label "Courses" names its list after the nav tab, as Add a player's "Players" does. The owner directed that layout and judges it at the click-through.
- **5, declined.** A yield fixture for one test adds lines and removes none. The engine is disposed before the assertions, and a GET that raises fails the test anyway.

**The owner's click-through**

On the phone, after restarting the demo, steps 1 to 3 were OK: Courses lists the golden tees with Add a course and tee at the top, a row opens its tee's page, and Add a course and tee opens the empty form. Step 4, the long course name, was skipped.
- **The wrap check: (c).** The step is accepted without it, since a course name wraps at its spaces and no course name has a word too long for the row.
- **The owner's finding: the sort was case-sensitive.** A tee added as "alfa" / "blue" listed after Trinity Forest Golf Club. Applied:
  - `load_tees` now orders by `lower(course)` and then `lower(tee_name)`, and names are still shown exactly as typed.
  - The store order test now saves Old Links "black" and a course "parkland" with the tee "blue". A case-sensitive order would put black after White and parkland after Trinity.
  - SQLite's `lower` folds only ASCII letters, so a name starting with Æ, Ø or Å still sorts by its code point, after Z and with Å before Æ. No such course is stored today.
  - Two tees whose names differ only in case have no set order between them.
