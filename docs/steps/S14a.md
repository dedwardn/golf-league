# S14a Services for admin: set up a season

**Implemented**

`services/setup.py` holds the admin's setup use cases:
- Create a player with a fresh link token, which is returned for the admin to send, and replace a player's link token.
- Create a tee, and change it only while `tee_locked` finds no card or team card on it in any season (R14).
- Create a season with its mode, rules, seed indexes, provisional flags and season teams in one transaction, refusing a team that names an unseeded player.
- Correct a seed index unless `seed_index_locked` says it is locked (R15).
- Create a round as a draft with its window. Before saving, the round is checked inside its season's `SeasonFacts`, and it refuses a format in an individual season and a `late_until` in a team season.

**Deviations from plan**

- Owner answer B: sim names moved to S19. The `sim_names` table, `save_sim_name`, the R14 one-or-more check and their tests were dropped, and `create_player` takes no sim names.
- Owner answer A(b): the window is a round fact. `RoundSetup` gains `opens_at` and `closes_at`, and `rounds` gains the two columns. The window is written by a new `save_window`, which the plan did not name. `save_round` was already at ruff's five-argument limit, and `RoundFacts` would have carried a field no domain code reads. So the window is written onto the round's row after it is saved, in the same transaction, the way `save_season_team` writes onto seeded rows.
- Owner addition: `create_season` refuses a season team that names a player with no seed index.
- The five round refusals are one parametrized test, `test_r13_r15_round_that_does_not_fit_its_season_is_refused`, with an id per rule, following `test_schema.py`'s `OUT_OF_SHAPE` precedent. The plan listed them as five named tests.
- `test_create_season_refuses_a_season_team_naming_a_player_without_a_seed_index` is new, for the owner's addition.
- No store test of its own for `update_seed_index`. The three seed tests in `test_setup.py` check it round-trips and leaves the same player's seed in other seasons unchanged.
- `test_schema.py` is not touched. Its DDL drift test covers the new columns as it stands.
- A private `_check_mode` holds the format and `late_until` refusals, directly above `create_round`.

**Open questions**

Answered in this step:
- **S12's carried season-team item.** A season team naming an unseeded player is now refused by `create_season` (owner addition), since `save_season_team` would drop that player silently. One player in two teams cannot happen, because `facts.teams` is a mapping.
- **S13's link token replacement** is `replace_link_token` (architect ruling 2).
- **S4 audit 11.** Admin input arrives as domain dataclasses (`Tee`, `SeasonFacts`) or is built into one (`RoundFacts` within `SeasonFacts`), so their bounds hold before anything is saved.
- **S2's provisional flag** is written by `create_season` and round-trips.
- **Names (S11, S12, S13):** ids double as names (owner answer A), so no table holds a name and the id the admin gives is what the screens show.
- **A round number already used:** if a draft round has it, the database's primary key raises IntegrityError. If an open or closed round has it, `SeasonFacts` raises ValueError. The architect accepted this (ruling 10), since `save.py` lets a broken key raise as it is.

- **To S14b:** whether the database ties `state` to `closed_at`, and whether `save_round` keeps taking them separately (S11, S12). The duel pairings gate and the config lock (S9b, S10). Refusing a player's own card in a shared-ball round at correction (S10). Whether a round's opens_at and closes_at become NOT NULL, written by save_round rather than save_window, once S14b settles what save_round takes (S14a audit finding 4).
- **To S15:** the seed shown as the index (S9b carried item 1).
- **To S19:** sim name uniqueness across players (owner question C).

Settled by the owner after the audit:
1. **No order check on the window.** Nothing checks that `opens_at` is at or before `closes_at`, because the glossary calls the window informational.
2. **Unknown ids are refused.** `replace_link_token` raises ValueError for a player who does not exist, and `correct_seed_index` for a player not seeded in the season. In both cases nothing is stored and nothing is returned. A seed correction that silently did nothing would give a player the wrong handicap all season. The two update functions now return whether they changed a row, and the service raises when they did not. Tests: `test_replacing_the_link_token_of_an_unknown_player_is_refused` and `test_seed_index_of_a_player_not_seeded_in_the_season_is_refused`.

**Audit**

The reviewer made 8 findings; the architect ruled on each.

1. The format and `late_until` checks are league rules and belong in `SeasonFacts`. Declined, except that the comment is fixed. The owner placed the rule in S14 at S13's audit (findings 3 and 4: "No domain change"), SPEC decision 4 names S14, and S13's tests put `late_until` on a T3 round. The comment that "nothing reads" a format elsewhere was false, because `takes_team_card` reads one in any season. It now says so.
2. The seeded team member check belongs in `SeasonFacts`. Declined. The owner placed the refusal in `create_season` by name. It guards a store write (`save_season_team` drops an unseeded member silently), not a rule the domain reads.
3. The team grouping exists in `setup.py`, `tests/fixtures/database.py` and `season.py`. Declined. The fixture is built only from save functions on purpose. Sharing with `season.py`'s private, sorted `_team_members` would need a new public domain name that only a store write uses.
4. `opens_at` and `closes_at` are nullable although every round has a window. Declined for S14a and carried to S14b (see Carried). Putting the window on `RoundFacts` would add a field no domain code reads, and passing it to `save_round` takes that function past ruff's argument limit.
5. `create_season` ignores `facts.rounds`. Declined. `SeasonFacts` is the dataclass that checks R15's teams, its six fields one by one would exceed the argument limit, and the docstring states that `rounds` is not read.
6. A round number held by a draft round had no test. Applied: `test_r13_number_of_a_draft_round_is_refused_by_the_key`. Its second call changes `closes_at`, so an upsert would show in the rows.
7. `test_setup.py` imports `t3_open` from `test_play.py`. Declined, on precedent: the store tests import from `test_save`, and S13 audit finding 6 declined the same kind of move.
8. The `create_player` docstring says the id is the displayed name. Declined, since owner answer A ("Ids double as names") says so. The answer is now recorded under Answered in this step.
