# S7 Standings

**Implemented**

A season or segment table is now computed from one season's awards. A player's round
total is their contest awards in that round; the table sums those totals over the closed
rounds it is given, or the best `best_n` of them chosen only from rounds the player scored
in, and then adds every manual award of those rounds in full. Every seeded player has a
row even at 0 points, and players level on points share a position and skip the next.

113 tests, 100 percent coverage of `league.domain`. 298 added lines and 1 removed across
five files, three of them in `src` and two new. Every accept criterion has a test: plain
sum, best N over fewer rounds, a round without an award offering no zero, a manual award
and a negative manual award surviving the round best N drops, a seeded player at 0, a
segment with its own best N, a shared position that skips the next with a shared first in
the same table, and the four bounds. Also edited at `/finish`: `docs/BUILD_PLAN.md`
(status) and `docs/ARCHITECTURE.md` (the three Public API cells).

`standings` has no caller outside tests. S9 is what builds `RoundAwards` from facts,
selects the closed rounds and calls it, once per table.

**Public API**

```python
# facts.py
@dataclass(frozen=True)
class Segment:
    name: str
    first_round: int
    last_round: int
    best_n: int | None = None
```

A named, inclusive range of rounds with its own optional `best_n` (R10). `ValueError`
when `first_round` is below 1, when `last_round` is before `first_round`, or when `best_n`
is below 1.

```python
# facts.py
@dataclass(frozen=True)
class StandingsRule:
    best_n: int | None = None
    segments: tuple[Segment, ...] = ()
```

How a table sums round totals (R10): all of them, or the best `best_n`. `ValueError`
when `best_n` is below 1, or when two segments share a name.

```python
# results.py
@dataclass(frozen=True)
class RoundAwards:
    number: int
    awards: tuple[Award, ...]
```

One round as a standings table reads it: which round, and every award it produced.

```python
# results.py
@dataclass(frozen=True)
class StandingsRow:
    position: int
    player_id: str
    points: Fraction
```

One player's line in one table. Players level on points carry the same `position`, and
R10 gives those rows no order of merit between them.

```python
# standings.py
def standings(
    rounds: Sequence[RoundAwards],
    seeded_player_ids: Sequence[str],
    rule: StandingsRule,
    segment: Segment | None = None,
) -> tuple[StandingsRow, ...]
```

The season table over those closed rounds, or that segment's, one row per seeded player,
ordered by points and then by player id so the table comes out the same every time. The
caller passes closed rounds only. No error path: every argument it could reject is a
shape a `Segment` or a `StandingsRule` already rejects.

**Deviations from plan**

1. `_check_best_n` is a private module-level function in `facts.py` called from both
   `__post_init__` methods, where the approved API said each bound goes in its own
   `__post_init__`. Both bounds are still raised from there. R10 states the bound once and
   both classes carry one message, so inlining would duplicate it. Validated by the owner
   before `/finish`, and again at audit: two callers in one module is not a cross-module
   helper.
2. `MIN_BEST_N = 1` and `MIN_ROUND = 1` were added beside `MIN_VIRTUAL_N`. The plan named
   the bounds but not the constants; `facts.py` already keeps every bound as one.
3. The plan's one test helper became two, `contest_award` and `manual_award`, and
   `contest_award` takes a `DuelReason`, so the negative contest award in the
   displaced-zero test reads as a loss rather than a win worth -1.
4. `test_r10_level_points_share_a_position_and_skip_the_next` carries a shared third as
   well as the shared first the plan asked for, so one table shows both skips.
5. `test_r10_a_segment_ends_no_earlier_than_it_starts` also constructs a one-round
   segment, which pins the range as inclusive where the error alone would not.

Applied at audit, both reversing an instruction in the approved plan:

6. `standings` takes `segment: Segment | None` rather than a segment's name. The plan had
   it take the name and raise on one that no segment carries. R10 states three errors and
   that was a fourth, invented by the signature: the only caller R10 implies is a pipeline
   that already holds `rule.segments` and iterates them, so an unknown name cannot reach
   it. The lookup loop, the `ValueError` and
   `test_r10_an_unknown_segment_name_is_an_error` are gone.
7. `RoundAwards` no longer carries `closed`, and the caller passes closed rounds only.
   The plan kept the flag so that R10's "over closed rounds" was enforced in R10's own
   module, and the owner argued for it twice. ARCHITECTURE's own convention settles it the
   other way: a result dataclass carries what a rule produced and the identity of what
   produced it, never an input the rule consumed, and a round's state is a fact under R13.
   It is also the call S4 already made, where the caller passes on-time entries rather
   than a flag. `test_r10_an_open_round_is_excluded` is gone and BUILD_PLAN moved that
   criterion to S9's accept line, which is where the pipeline decides what is closed.

Also applied at audit, from R10's three clarifications in commit `b942c96`:

8. A segment's first round must be 1 or more, with
   `test_r10_a_segment_starts_at_round_1_or_later`. Without it, `Segment("x", -3, 0)` was
   legal and matched no round, which is the silent nothing every other bound here exists
   to stop.
9. The second paragraph of `_check_best_n`'s docstring is gone. It argued for a bound that
   R10 now states outright, which is narration, not a why.
10. `test_r10_a_segment_ends_no_earlier_than_it_starts` no longer asserts
    `Segment("autumn", 2, 2).last_round == 2`. Not raising is the behaviour; the assertion
    only echoed its own input.

No code change for the other two clarifications: manual awards in a segment table come
from that segment's rounds only, which is what the code already did and what R10 now
says, and the rows of a shared position carry no order of merit, which is why they stay
ordered by player id — for a stable table, not as a ranking.

Nothing else differs. The five planned files are the five files changed, the two dropped
fields stayed dropped, and no helper beyond the planned five exists.

**Deliberately not done**

- Building `RoundAwards` from facts, selecting the closed rounds, `RoundView`,
  `SeasonView` and `compute_season`. S9, which is also where `RoundView` will hold a
  round's `RoundAwards` rather than repeat its fields.
- Any tiebreak. R10 orders on points alone, and naming a winner out of a shared first is
  open decision 5, due before a season or segment ends.
- `cards` on a row and `card_player_ids` on `RoundAwards`. Nothing reads a card count
  now; the step whose code needs one adds the field.
- The pairing order of R11, which reads a table and then separates a shared position by
  index and player id. S8.
- Formatting points or positions as strings. The view objects, S9 onward.
- An error for an award whose player is not seeded. S9 builds both lists from the same
  season facts, so it cannot arise there.

**Open questions**

1. `standings` keys its rows by player id, so a repeated id in `seeded_player_ids`
   collapses to one row and an award for a player not in that list is ignored without a
   word. Both are impossible once S9 builds the list from the season's seed indexes.
   Worth a bound there rather than here, but it is S9's to place.
2. Open decision 5 now only names a winner, so S7 did not need it. It is still unanswered
   before a season or segment closes, and S15's standings screen will show a shared first
   with no winner named.
3. S9 decides whether a season view computes every segment table eagerly or on request.
   Each one is another pass over the same awards, which at 300 cards costs nothing, so
   eagerly is probably right, but nothing here assumes it.
