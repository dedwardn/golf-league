# S17e1 Cards on a round

**Implemented**

- An open or closed round's admin screen has a Cards card under its state card. In a team season an own-ball round has one row per player and a shared-ball round one per team. Teams are in team id order, with each team's players together in player id order.
- A row with a counted card or team card reads its holder, its gross, "In {submitted_at}" in local time, and Void. A row without one reads "No card". A late card reads as any counted card.
- Void is a link. It changes nothing and redraws the screen with that row asking "Void {holder}'s card? It stops counting and cannot be undone. {holder} can hand in a new one while the round is open.", with "Yes, void it" and Cancel. The round card is hidden while a row asks.
- Each row has the id `row-{holder}`, taken from the holder so a voided row keeps it. Void, Cancel and Yes's form end with that fragment, and Yes's redirect names none, so the browser keeps the fragment it posted to and the page opens on that row each time. No script.
- Yes voids the card through `void_card` and opens the round's page. A post that `void_card` refuses stores nothing and opens the page, with no worded refusal.
- `round_cards_view` is the use case that lists a round's cards with their ids. S14c left it for S17.

5. **Applied.** The web tests import `a_draft`, `actions` and `state` from `test_admin_round.py` in place of their own copies.
6. **Sent to the owner, who chose neither (a) nor a parked step.** The lookup of a round by number is now in `round_cards.py`, `round_result.py` and `entry.py`, with a variant in `bay.py`. S17e2 opens with a refactor-only commit that moves them onto a `SeasonFacts.round(number)` method.
