# S0 Guardrails

**Implemented**: an empty package with five layers, the quality gate, and the Claude Code setup. No league logic exists yet.

**Where**
- `pyproject.toml`: dev tools and their settings (ruff budgets, pyright strict on src, import-linter contracts, vulture, coverage gate of 95 percent on `league.domain`).
- `scripts/check.sh`: the single gate. `scripts/check_structure.py`: one home per public name, 300 lines per file.
- `src/league/{domain,store,extract,services,web}/__init__.py`: one-line purpose each.
- `.claude/settings.json`: plan mode by default, allowed commands, prompts before edits to guardrail files, format-on-edit hook.
- `.claude/skills/{step,finish,audit}`, `.claude/agents/reviewer.md`: the step workflow.
- `docs/`: SPEC, ARCHITECTURE, BUILD_PLAN, LEAGUE_DESIGN, DECISIONS, WORKFLOW.

**Public API**: none.

**Verified on 2026-09-19** (uv 0.8, Python 3.13, ruff 0.16, vulture 2.16): the gate passes on the empty skeleton, and each guardrail was shown to fail when broken: a domain import of `league.store`, a domain import of `sqlalchemy`, the same public function name in two modules, an unused function, a 301-line file.

**Not verified**: the Claude Code files (`settings.json`, skills, reviewer agent, hook) follow the current documentation but have not been run in a live Claude Code session. First use of `/step S1` is the test.

**Deliberately not done**: runtime dependencies, database, web app, CI. Each arrives with the step that needs it.

**Open questions**: the six owner decisions at the end of SPEC.md.
